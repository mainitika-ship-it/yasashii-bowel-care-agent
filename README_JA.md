# Yasashii Bowel Care Agent

**家族介護の記録を支え、不確かなことは人へ。**

排便の様子、記録、次の人への申し送り。家族介護には、覚えておくことがたくさんあります。Yasashiiは、その整理を助けるAIの試作です。

**AIが手伝い、人が決める。** 現在は模擬データで動作を確認した段階です。完成した介護製品・診断機器ではありません。

[▶ 動画を見る](https://www.youtube.com/watch?v=Cuf4LXeQJCU) · [English](README.md) · [構成図](docs/architecture.md) · [検証記録](docs/verification_2026-09-11.md)

## まず、この3つだけ

| 表示 | 何をする？ | 申し送りへ |
|---|---|---|
| ✓ **PASS — Record** | 入力がソフトウェアの基準を満たしたら、観察を記録。 | 入れる |
| ? **HOLD — Ask a person** | 不確かなら、人の確認待ちとして保存。 | 入れない |
| ! **STOP — Stop & alert** | 通常の観察記録を止め、安全警告を別に残す。 | 入れない |

**保存済みの3ケースでは、申し送りはPASSの1件だけです。** HOLDは確認待ちの保存まで。人への自動通知や、承認画面が完成したという意味ではありません。

## どう動く？

![模擬入力をQCで確認し、Strandsが操作を選び、ガードが許可された記録だけを実行する。PASSだけ申し送りへ。](docs/architecture-ja-en.png)

大きい英語の下に、日本語を添えています。[図を大きく開く](docs/architecture-ja-en.png)

1. **ルールで先に確認**：入力の形式・信号・不確かさを確認。
2. **AIが操作を選ぶ**：ここにStrands Agents SDKを使用。
3. **ガードが実行を確認**：違う操作・架空の値・同一実行内の二重記録を拒否。
4. **行き先を分ける**：観察記録・確認待ち・安全警告へ。

実演の入力は、用意した模擬JSONです。カメラとの統合は未検証です。オフライン実行と個人情報フラグ付き入力では、AIを呼びません。

## 手元で試す：最初の1行

Python 3.10以上を使います。READMEが入ったフォルダで、ターミナルに貼り付けてください。

```bash
python3 src/demo.py --mode offline
```

AWS・認証情報・追加パッケージは不要です。**このモードではAIモデルを動かしません。**

表示された `view_path` の `report.html` をブラウザで開きます。PASS・HOLD・STOPが各1件、申し送りが1件なら想定どおりです。毎回別のフォルダへ保存するので、前の結果と混ざりません。

画面は閲覧専用です。承認ボタンはまだありません。

## Macの実モデルで試したい場合

まず、同じフォルダで準備を確認します。

```bash
python3 src/check_local_setup.py
```

インストール済みモデルとPythonパッケージの確認だけを行います。モデルの追加・AI推論は行いません。準備後の実行方法は、[ローカル実行ガイド](docs/local_model_guide.md)と[英語README](README.md)にあります。

保存済みの成功結果を見るだけなら、実モデルを再実行する必要はありません。Bedrockの成功実行は未確認です。
